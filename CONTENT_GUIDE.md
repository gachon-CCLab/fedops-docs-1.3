# FedOps content publishing

Docs, Blog, and News are built together from this repository. A push to `main` runs one Jekyll build and publishes all three sections:

- Docs: `/`
- Blog: `/blog/`
- News: `/news/`

The public base URL is `https://gachon-cclab.github.io/fedops-docs-1.3/`.

## Add a Blog or News post

Create a Markdown file in `_blog/` or `_news/`. The filename becomes the public URL slug. Use a short, stable slug for new content; existing imported posts keep their original IDs so their links remain traceable. For example, `_blog/fedops-release.md` becomes `/blog/fedops-release/`.

```md
---
title: "FedOps release"
summary: "One-sentence description for the listing page."
category: Development
author: FedOps
date: 2026-09-22
display_order: 0
---

Write the article here in Markdown.
```

`title`, `summary`, `category`, and `display_order` are used on the listing page. Add `date` for dated posts. Lower `display_order` values appear first; the imported posts retain their original order. For the next new post, use a value lower than the current smallest value in that section (for example, `0`, then `-1`). Add images under `assets/blog/` and reference them with `{{ '/assets/blog/image.png' | relative_url }}` so links work under the GitHub Pages base path. News posts may include `source_url` for the original paper or announcement.

## Edit Docs

The 1.3 overview is `index.md`, and the 1.3 guides are in `v1.3/`. The legacy 1.2 documents remain in `v1.2/` and `docs/`. Some 1.3 guides are generated by `scripts/import_guides.py` from exported source files; edits to those generated files can be replaced by a later import. Check `DOCS_1_3_README.md` before changing them.

## Preview and publish

Run `bundle exec jekyll build --baseurl /fedops-docs-1.3` to build the complete site. Run `npm ci` once, then `npm run format:content` for manually maintained 1.3 Docs pages and Blog/News Markdown, and `npm run check:content` before committing. The Docs, Blog, and News deployment uses the same `Gemfile` and GitHub Actions workflow. Imported Docs pages are excluded from automatic formatting because `scripts/import_guides.py` regenerates them from exported source files.

The two shared color seeds (`--fedops-primary` and `--fedops-secondary`) are in `assets/css/fedops-tokens.css`. Dark, soft, and border shades derive from those seeds. Both Docs and the Blog/News layouts load that file, so a seed change applies across all three sections. The old `fedops-publications` Pages site only redirects existing links to this site and is no longer a content source.
