# FedOps Launcher: Flower App Hub의 GFedOps App을 실제 참여형 연합학습으로 연결하는 실행 환경

![FedOps Launcher]({{ '/assets/blog/69e53c948e8a8ccf7992194a-body-1.png' | relative_url }})

**FedOps Launcher**는 [**Flower App Hub**](https://flower.ai/apps/)에 게시된 **[GFedOps](https://flower.ai/profile/gfedops/apps/)** App을 보다 쉽게 실행하고, 실제 연합학습 참여까지 자연스럽게 연결할 수 있도록 설계된 **FedOps 기반 클라이언트 실행 환경**입니다.

[FedOps Launcher Document](https://gachon-cclab.github.io/docs/FedOps-Launcher)

## Flower App Hub에서 실제 참여형 연합학습으로

**Flower App Hub**는 연합학습 애플리케이션을 게시하고, 탐색하고, 재사용하고, 다양한 환경에서 실행할 수 있도록 지원하는 중요한 생태계입니다. 이를 통해 개발자와 연구자는 별도의 복잡한 실행 인프라를 처음부터 직접 구성하기보다, 애플리케이션 자체의 구조와 실험, 그리고 확장에 더 집중할 수 있습니다. 특히 Federated App을 표준화된 형태로 공유하고, 서로 다른 환경에서도 재현 가능하게 실행할 수 있도록 한다는 점에서 **Flower App Hub**는 협업형 AI 생태계의 중요한 기반을 제공합니다.

**GFedOps**는 이러한 **Flower App Hub**의 장점을 적극적으로 수용하면서도, 한 걸음 더 나아가 **실제 클라이언트가 참여하는 연합학습 운영 환경**에 초점을 맞추고 있습니다. 많은 연합학습 예제와 실행 흐름은 로컬 시뮬레이션이나 단발성 실험 재현에는 적합하지만, 실제 사용자가 자신의 환경에서 연합학습 클라이언트로 참여하고, 로컬 학습을 수행하며, 학습 결과를 연합학습 파이프라인에 연결하는 단계까지 자연스럽게 이어지기 위해서는 추가적인 실행 환경과 운영 편의성이 필요합니다. **GFedOps**는 바로 이 지점을 중요하게 보며, **Flower App Hub**의 앱 공유·재사용 생태계를 **실제 참여형 연합학습 경험**으로 확장하는 것을 지향합니다.

## 기존 참여 방식의 한계

기존의 FedOps 기반 연합학습 참여 방식에서는 사용자가 직접 Python 실행 환경을 구축하고, 필요한 패키지와 의존성을 설치하며, 클라이언트 코드와 매니저 코드를 각각 준비하고 실행해야 했습니다. 이 과정은 연합학습 구조를 잘 아는 사용자에게도 번거롭고, 처음 접근하는 사용자에게는 상당한 진입장벽으로 작용할 수 있습니다.

즉, 연합학습에 참여하기 위해 필요한 핵심은 로컬 데이터 기반 학습과 안전한 파라미터 교환이어야 하지만, 실제로는 그 전에 환경 구성과 실행 절차 자체가 더 큰 부담이 되는 경우가 많았습니다.

## FedOps Launcher의 역할

**FedOps Launcher**는 이러한 복잡성을 줄이기 위해 개발되었습니다. FedOps Launcher는 Docker 이미지 및 컨테이너 기반으로 동작하는 실행 환경으로, 운영체제에 관계없이 일관된 방식으로 실행할 수 있도록 설계되었습니다. 이를 통해 사용자는 개별 시스템에서 Python 버전, 패키지 충돌, 실행 방식 차이 등을 일일이 맞추는 대신, 준비된 환경 안에서 바로 FedOps 클라이언트를 실행할 수 있습니다.

![기존 FedOps 기반 참여 흐름]({{ '/assets/blog/69e53c948e8a8ccf7992194a-body-2.png' | relative_url }})

다시 말해, FedOps Launcher는 연합학습 참여에 필요한 복잡한 실행 준비를 컨테이너 내부로 추상화하여, 사용자가 연합학습 애플리케이션 자체와 참여 흐름에 더 집중할 수 있도록 합니다.

![FedOps Launcher 실행 흐름]({{ '/assets/blog/69e53c948e8a8ccf7992194a-body-3.png' | relative_url }})

## FedOps Launcher의 실제 사용 흐름

FedOps Launcher의 핵심 가치는 단순히 "도커로 실행된다"는 점에 있지 않습니다. 더 중요한 것은, **Flower App Hub**에 게시된 **GFedOps** App을 사용자가 실제로 활용하고, 수정하고, 연합학습 작업에 참여할 수 있는 **실행 가능한 사용자 경험**으로 연결해 준다는 점입니다.

실제 사용 흐름은 다음과 같습니다.

1. **CreateFL** 기능을 통해 **Flower App Hub**의 **GFedOps** App을 Launcher 내부로 손쉽게 내려받습니다.
2. VSCode와 유사한 코드 편집 UI와 터미널 환경에서 필요한 부분을 수정하거나 실행 전 테스트를 진행합니다.
3. 필요 시 프로젝트 의존성을 설치한 뒤, **Task** 기능을 통해 자신이 참여할 FedOps 기반 연합학습 작업을 선택하고 설정을 적용합니다.
4. **Run** 버튼을 통해 연합학습 클라이언트를 실행하면, 로컬 학습 수행과 파라미터 송수신, 그리고 연합학습 파이프라인과의 연결이 자연스럽게 이어집니다.

이 과정에서 사용자는 복잡한 시스템 운영 절차보다 **실제 연합학습 참여 자체**에 집중할 수 있습니다.

## 단순 실행 도구를 넘어서는 실행 계층

이러한 점에서 FedOps Launcher는 단순한 보조 실행 도구가 아니라, **Flower App Hub**의 개방성과 재사용성을 실제 참여형 연합학습 운영으로 연결하는 실행 계층이라고 볼 수 있습니다.

**Flower App Hub**가 federated app의 공유, 탐색, 재사용, 재현 가능한 실행을 위한 생태계를 제공한다면, **GFedOps**와 FedOps Launcher는 그 위에서 사용자가 실제 클라이언트로 참여할 수 있도록 실행과 운영의 진입장벽을 낮추는 역할을 합니다. 즉, 앱을 "발견하는 것"에서 끝나는 것이 아니라, 그 앱을 자신의 환경으로 가져와 실제로 실행하고, 수정하고, 연합학습에 참여할 수 있도록 만드는 것이 FedOps Launcher의 핵심 목적입니다.

## GFedOps 생태계 확장 관점에서의 의미

또한 **GFedOps**는 **Flower App Hub**를 통해 다양한 FedOps 기반 App들을 제공함으로써, 사용자가 단순 예제를 소비하는 수준을 넘어 자신의 프로젝트와 환경에 맞게 연합학습 애플리케이션을 확장할 수 있는 출발점을 제공하고자 합니다.

FedOps Launcher는 이러한 **GFedOps** App 생태계를 실제 사용자 관점에서 실행 가능하게 만드는 핵심 구성 요소이며, 연구용 실험에서 실제 운영형 연합학습으로 나아가는 과정의 간극을 줄이는 역할을 수행합니다. 이를 통해 사용자는 로컬 시뮬레이션이나 정적인 예제 실행에 머무르지 않고, 자신의 장치와 환경에서 실제 연합학습 참여 클라이언트로 동작하는 경험을 보다 쉽게 시작할 수 있습니다.

## 마무리

결론적으로, **FedOps Launcher**는 **Flower App Hub**의 장점을 계승하면서, **GFedOps**가 지향하는 **실제 클라이언트 참여 기반 연합학습**을 보다 쉽고 실용적으로 구현하기 위한 실행 환경입니다. 이는 연합학습 애플리케이션의 공유와 재사용을 넘어, 사용자가 자신의 환경에서 곧바로 실행하고 참여할 수 있는 형태로 연결한다는 점에서 의미가 있습니다.

**GFedOps**는 **Flower App Hub**를 통해 재사용 가능한 연합학습 앱 생태계를 구축하고, FedOps Launcher를 통해 그 생태계를 실제 참여형 연합학습 경험으로 확장하고자 합니다. 이러한 구조를 통해 우리는 연합학습이 일부 숙련된 사용자의 복잡한 설정 작업이 아니라, 더 많은 사용자와 기관이 쉽게 접근하고 참여할 수 있는 실용적 협업 AI 환경으로 발전할 수 있다고 보고 있습니다.
